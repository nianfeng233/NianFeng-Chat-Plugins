# 念风 · 知识库（独立扩展）

这是一个**不进入主仓库构建**的外部扩展，放在 `extensions/knowledge-base/`，由安装脚本复制到外部插件目录后生效。

它给模型提供一组本地知识库工具。模型可以把联网搜不到、容易过时、个人化、设定类的信息规范地写进本地库；下次需要时先检索，再读取原文。检索体验类似“把资料先存进一个本机的小型维基，然后像搜索一样查找”。

## 给模型的工具

| 工具 | 用途 |
|---|---|
| `kb_search` | 本地混合检索：关键词 + 可选语义向量 + 标签 + 目录前缀 + 更新时间；只返回预览和 ID |
| `kb_read` | 按 ID 读取全文；长文按 offset / max_chars 分段；可返回历史版本摘要 |
| `kb_write` | 新建知识条目；`path` 自动建立多级目录；同一 `path + title` 默认更新 |
| `kb_edit` | 编辑条目：改标题 / 目录 / 正文（替换、追加、前置）、增删标签、改 metadata |
| `kb_tree` | 查看多级目录和当前目录下直接条目；写新条目前先看已有路径 |
| `kb_delete` | 软删除条目或目录；必须先征得用户同意并传 `confirm=true` |

工具描述里已经写明“什么时候用、写前先查重、目录怎么分层、删除前先确认、不要根据预览猜内容”等约束。

## 在界面里查看知识库

念风侧边栏的「记忆与知识库」页面内置「知识库」标签页，读取本扩展的后端接口：

- `GET /api/knowledge/entries`：分页浏览 / 搜索有效条目（支持 `q`、`path`、`tags`、时间过滤、`limit` / `offset`）；
- `GET /api/knowledge/entries/:id`：读取单条知识全文，并附带历史版本摘要。

页面只读，不会修改数据；写入 / 编辑 / 删除仍由模型工具或未来的管理功能完成。未安装本扩展时，页面会提示先安装并重新扫描。

> 删除是软删除，但模型必须先征得用户明确同意后才应传 `confirm=true`；目录删除再传 `recursive=true`。

## 数据模型

- 条目字段：`id / path / title / content / tags / metadata / revision / created_at / updated_at`
- **多级目录**：`path` 使用 `/` 分隔，例如：

```text
崩坏：星穹铁道/星神/命途
崩坏：星穹铁道/怪物
个人资料/偏好/写作风格
```

不需要单独创建目录；写条目时 `path` 自动形成目录树。

- **标签**：一个条目可以有多个标签，检索时可按 `all` / `any` 过滤。
- **时间戳**：记录创建时间、更新时间、最后访问时间；搜索可按 `updated_at` 前后过滤。
- **历史版本**：每次编辑保留旧版本，每个条目最多 50 版。

## 检索设计

1. 写条目时会把 `title / path / tags / content` 预先切成检索 token；中文按二元组，英文按单词。
2. 搜索时：
   - BM25：标题权重 6、标签 4、目录 3、正文 1；
   - 可选语义：如果配置了向量模型，会把 query 和条目摘要做 embedding，用余弦相似度排序；
   - RRF（k=60）融合关键词排名和向量排名；
   - 再叠加目录前缀、标签、时间过滤。
3. 如果没配向量模型，自动降级为纯关键词 + 标签 + 目录检索，功能不受影响。

这种设计比纯 LIKE 更准，也比“每轮都调模型做搜索”更省 token：检索在本地完成，模型只在需要时调用工具。

## 配置

- 无需配置也能使用：默认纯 M​​arkdown / 文本关键词检索。
- 想开启语义检索，只需要在念风「设置 → 模型 → 记忆模型」里配置一个向量模型；知识库会自动复用它的 embedding 配置。
- 也可以在插件自己的 `config.json` 中用 `embeddingProvider` / `embeddingModel` 覆盖；`autoEmbed=false` 可关闭写入时的向量化。
- 数据文件：`<数据目录>/knowledge-base/knowledge.db`（旧 Node 环境回退 `knowledge.json`）。

## 安装

```powershell
powershell -ExecutionPolicy Bypass -File .\extensions\knowledge-base\install.ps1
```

也可以指定数据目录或外部插件目录：

```powershell
powershell -ExecutionPolicy Bypass -File .\extensions\knowledge-base\install.ps1 -PluginsDir "D:\my-plugins" -Force
```

也可以直接在「设置 → 插件 → 添加插件」上传 `knowledge-base-v2.0.0.zip`。

安装后到「设置 → 插件 → 重新扫描」，确认知识库已加载。数据文件不会进入主仓库构建。

## 使用示例

给模型说：

> 把下面这条设定记到知识库：路径「崩坏：星穹铁道/星神/命途」，标题「毁灭星神」，标签「星神、毁灭、设定」，内容是……

之后问：

> 之前记的毁灭星神设定是什么？去知识库搜一下。

模型会走 `kb_search` → `kb_read`，而不是凭空回答。

## 设计取舍

- 不进入 package-release 本体：满足“独立维护、按需安装”。
- 不在每轮对话里自动把知识库塞进上下文：避免 token 爆炸；由模型按需工具调用。
- 本地存储 + 本地检索：核心信息不需要联网，也不占用主聊天模型上下文。
- 目录不建表：从路径反推，模型写条目时更省心，也避免“空目录”管理负担。
